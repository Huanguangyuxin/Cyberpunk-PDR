每轮 Gemini 修改必须实际执行：DCC源→不可变导出→官方导入→运行出帧→固定机位截图→独立审查→按问题修正。运行的生产者、导出者、集成者分别记账；本轮Gemini实际用Blender CLI/Python，不宣称使用MCP。先保存失败源与图，再产生下一版；不以聊天完成话术或手写hash替代实际文件。源与截图必须绑定确切hash，旧图不得自动算新源结果。

## R4之后的全场执行次序

1. 以A1/055源、R4原生截图与acceptance.md为输入，先修水边/下梯及桌边实际观察面的灯具开口/已有灯组覆盖；32原生cap、主要建筑/家具/机位与尺度不变。不将诊断L补光算夜景通过。
2. 全场材质按统一三层体系完成年代/工艺精修，优先VIP/卡座与维修接触边；交付实际中性样板/UV密度与源材质、真实Engine对照，不靠更多垃圾/海报数量。
3. 用确定方向的法线测试样本完成normal-Y/手性像素契约，再分别验证实际阴影、局部反射/SSR/体积；未运行保持未验证，不改SDK核心或盲开全部效果。
4. 同一版全场DCC→确定导出→官方导入→实际运行→19机位/原9净图→独立空间/风格复审。两个既存缺口及新实际缺陷闭合后才进行完整高保真终验；当前仅v3已落地纠偏检查点，不冒称完成最终PDR。

## 阶段与依赖

### S0 方法学习与长期规范（已完成的前置任务）

输入：用户要求、原始教程、现有本地资料。输出：六份长期文档、根工作区导读、来源与一致性记录。验收：读到原始文字全文；区分原文/用户/扩展；未调用制作；检查约束与链接。本阶段完成不表示全场设计完成。

### S1 全场设计启动与信息核实

依赖 S0。核实当前项目入口和版本；只读检查 Cursor 实际 Gemini 名称、调度方式、Blender 与引擎工作流；收集原作视觉参考。梳理显示平台、目标分辨率、目标帧率/帧时间、演示路径、相机、交付范围和资产许可；已明确约束不重复询问，只问真正影响设计的缺口。

交付：参考登记、设计 brief、已知/未知能力清单、历史 V3 冲突清单、统一坐标候选、全场设计任务分派。验收：无未标注假设；工具能力有证据分级。不能通过“接口存在”认定生产可用。

### S2 完整场景设计

依赖 S1；以下设计任务可基于同一平面基线协调并行，但不能彼此独立发明布局：

- 美术方向：全场概念和分区情绪/焦点；不生成最终 3D。
- 空间设计：米制平面、两条剖面、二层和楼梯、净通路、舞台朝向与视线。
- 灯光设计：灯位与灯具、照射逻辑、阴影/体积/反射需求、曝光与后处理。
- 材质设计：全场材质库、区域分配、PBR 与透明需求、纹理尺度与引擎映射。
- 资产规划：覆盖全部区域的资产清单、Hero/模块/布景层次、预算候选、依赖和分工。
- 引擎技术调查：接口与现有文件核实、差距和风险；不能在设计未齐时批量造资产。

输出须满足 ART_DIRECTION 的完整设计包。闸门 G-D：所有图纸同版且覆盖全场，尺寸与空间冲突关闭；未验证技术风险有处置方案；独立设计审查完成，用户审阅确认设计方向与完整包。未过 G-D，不能开始 S3 批量生产。

### S3 完整场景制作与管线验证

依赖 G-D。先建立贯穿全场的空间骨架与尺度关系，再按区域/资产族推进完整资产、材质和灯具；不把某一个小房间精修到终版作为总体制作策略。单资产导入探针只验证格式/材质/单位。

角色：建筑/模块资产、Hero 道具、材质纹理、灯具/布景各有专门执行者；集成者管理共享源。输出：全场版本化 DCC 源、可重复脚本、纹理与资产契约、导出候选包、结构自检证据。闸门 G-P：全区域覆盖、比例/接触/拓扑/依赖检查通过；完整清单可重建；不把 Blender 美图作为引擎通过证据。

### S4 自研引擎集成

依赖 G-D 及已检查资产；S3 生产中的合格候选可逐批集成，但 S4 完成依赖 G-P 全场交付。读取子工程 AGENTS/README 与相关能力技能，沿用实际引擎资产入口和 GUID，不手写构建投影或另造生命周期。

输出：版本化导入映射、实际引擎场景、灯光材质与后处理配置、固定相机、全场截图和日志、性能记录。验证 PBR、阴影、局部反射、透明、水、体积、后处理，覆盖所有区域。闸门 G-E：实际运行成功、资产依赖完整、关键渲染功能实证通过；能力缺失仍开放则不得称全场高保真已完成。

### S5 独立视觉审查与迭代

依赖引擎候选和完整证据。每轮执行 METHODOLOGY 的固定截图与问题协议：制作者提交→独立 Critic 判断→Codex 分派问题→修复→同条件复拍→独立复验；新缺陷单独登记。参考、图纸或配置变更须有决策记录并保留旧条件回归图。

输出：每轮问题列表、截图与评分、修复差异、回滚点。G-V：阻断/主要缺陷清零、全区域通过、引擎证据真实、目标平台性能实测符合已冻结目标；评分仅为辅助。不得删掉难看机位、换曝光掩盖问题或拿概念图顶替。

### S6 交付与恢复验证

依赖 G-V。整理完整源、脚本、引擎包、依赖与来源、真实效果画廊、已知限制和恢复说明；在干净/可复现环境验证实际启动与关键机位，执行一次恢复或回滚验证。未演练则明确未演练并保留该项未完成。同步进度与决策，交付给用户复核。

## Agent 角色、权限与依赖

Codex 主协调维护 brief、版本、任务依赖、合并和记忆。计划由 Cursor Gemini 执行设计/制作/引擎子任务，须先验证实际调度能力；可按需要串行承担专业角色，不伪称已并行。视觉 Critic 必须是与制作者独立的审查执行者，先看参考和实图再读制作解释。

空间 Agent 提供共享坐标和图纸；概念 Agent 依图发展形象；材质/灯光 Agent 不改建筑范围；资产 Agent 不改方向和单位；集成 Agent 独占引擎全局配置合并。Critic 只出审查结果，不修改生产文件。并行只在写入集合互斥、输入版本一致时开展。

## 每次 Gemini 派工模板

- task_id、角色与实际模型身份；当前阶段、目标和禁止事项。
- 必读 AGENTS、五份相关文档、子工程规则的可访问路径及版本/哈希；执行者回执已读和提取到的关键约束。
- 输入版本、依赖任务与已冻结决策 ID；不得未经说明更换基线。
- 输出文件、稳定资产 ID、写入白名单/独占锁；单位、坐标、材质与预算契约。
- 工具实际调用方式与记录位置；不得编造 CLI、截图接口、模型输出。
- 验收项、独立审查者、必需截图与日志、失败退出和回滚点。
- 返回变更摘要、输出哈希、真实验证、已知问题、未验证项；更新进度/决策的候选补丁由协调者串行合并。

当前不填造 model/run_id 等已执行字段，不自动发送给未接通的 Cursor。

## 正式启动完整设计阶段的首批执行顺序

1. 重读长期文档，登记实际 Cursor/引擎工作目录和只读能力检查结果。
2. 整理丽姿原作参考及已有 V3，提出需要用户决定的少量关键缺口，继续做不依赖答案的参考分析。
3. 校核全场米制平面与两条剖面，先解决舞台、二层楼梯、水带净路和尺寸链。
4. 在同一空间基线上完成多视角概念、灯光图、材质板和资产表；逐项标明真实引擎实现需求。
5. 组织独立设计审查，修订完整包并提交用户审阅；通过 G-D 后才派发完整场景生产。
